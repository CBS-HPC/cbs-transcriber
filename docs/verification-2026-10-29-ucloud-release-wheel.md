# UCloud release-wheel source — 29 October 2026

T94a is verified offline. This is not an application activation or clean-machine acceptance claim.

The [28 October installation audit](audits/installation-2026-10-28.md) recommended replacing
the Git source for ucloud-workflow with the equivalent released wheel. This source-only
change pins `ucloud-workflow==0.1.9`, sets its official HTTPS wheel in `tool.uv.sources`, and
uses a lock generated by uv 0.9.29. No lockfile entries were edited by hand.

Git remains needed to clone/update this app's source. Source-ZIP installation through the
documented uv workflow no longer has a Git-sourced dependency. Public app availability,
anonymous clean Windows installation and real Apple Silicon/Intel Mac acceptance remain
separate from the evidence below. No standalone pip installation or desktop installer is
provided by this change.

## Package plans and runtime boundary

Using absolute uv/Python paths and an **empty child PATH** (no Git executable), all three
`uv sync --locked --offline --dry-run --project <candidate> --python-platform <target>`
plans passed:

- Windows x64: `x86_64-pc-windows-msvc`;
- Intel macOS core: `x86_64-apple-darwin`;
- Apple Silicon: `aarch64-apple-darwin`, with child-only `MACOSX_DEPLOYMENT_TARGET=14.0`.

The plans created no `.venv`, changed no candidate lock bytes and installed/downloaded
no dependencies. These are warm-cache package-selection checks, not fresh installation
or native Mac execution. Intel local inference remains excluded; Apple Silicon still
requires macOS 14+ for the locked CPU local stack.

The serving environment was neither installed into nor synchronized. Mocked integration
uses the existing interpreter with the verified wheel extracted into a temporary directory;
before pytest, guards require both the imported module and distribution metadata to come
from that directory. No private library, credentials, model weights or provider is used.
