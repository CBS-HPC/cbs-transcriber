# Post-MVP work: audit and proposed sequence

10 November 2026, Europe/Copenhagen. This is a planning document, not permission to start
every item or resume parked work. The installed/published baseline remains MVP 0.1.0.
Application source has not changed during this planning review. No live provider tests,
private uploads, model downloads, new cloud jobs or backup transfers are added by this plan.

The current [TODO](../../TODO.md) mixes missing implementation, implemented features awaiting
acceptance, historical branch notes and explicit holds. An unchecked umbrella item does not
mean every part of that feature is missing. Two independent read-only reviews informed this
audit; archived worklists and old branch names are historical evidence.

## What the larger workflow items actually involve

**Broader editor redesign.** Text replay, double-click word selection, compact Word and timing
controls, timing-preserving manual saves, Undo split/merge and individual deleted-passage
restoration already exist. Remaining questions are how Text/word/timing controls should be
organized, how timing is corrected while listening, which controls belong inside each passage,
keyboard/accessibility behavior and how an editable highlighted area should behave. Word-
following and technical safety prototypes can start independently. Final organization should
use observations about what the colleague actually searches for and edits.

**Review workflow and manual history.** Not checked/Checked/Needs review, persistence and
Next to review are shipped. Remaining work includes useful status filters, tags for newly
re-transcribed passages, consistent review state through edits/structure/results/exports,
an understandable per-passage change history and broader rollback beyond supported inverse
actions. Feedback helps decide terminology, granularity and whether these additions reduce
review effort; existing controls should not be rebuilt merely because the umbrella row is open.

**NVivo and REFI-QDA.** Native Windows/Mac transcript formats, Word/text exports, selection and
named project ZIPs exist. Actual NVivo versions must demonstrate import, Unicode/speakers,
timeline synchronization, edited/split/merged rows and coding behavior. Synthetic packs are
oracles, not proof of compatibility. REFI codebook/project interchange is separate future
engineering for codes, passages and memos, not an already working export. Use the
[real NVivo plan](mvp-nvivo-test-plan-2026-11-11.md) before choosing interoperability changes.

**Spelling assistance — parked.** There is an unmerged/unpushed local prototype, not a blank
implementation: Danish checking, British English suggestions, private vocabulary and bounded
worker/cache controls. Danish suggestions were disabled after timeouts. A new decision is
needed before resuming integration with the final MVP editor; remaining gates include quality,
performance, dictionaries/licensing, platform checks, language choice and draft/timing safety.

**CBS Runtime — parked.** This is separate from native UCloud Transcriber. Its unresolved
preparation-lock ownership/recovery needs a safe design; an isolated-generation prototype is
disabled. Later acceptance includes pinned model preparation/reuse, CUDA/MIG memory, a real
batch, Stop/recovery and cleanup. A terminal owner is not permission to steal a lock. Do not
start preparations or paid jobs while this work is held.

**Anonymisation — parked.** Only design and a synthetic demonstration exist. There is no in-app
detector/review workflow. It needs an agreed identifier scope, evaluated Danish/English
detection, human review of spans, consistent pseudonyms where needed, key custody/retention,
separate derived results and export-leak tests. Text redaction does not anonymise voices,
original audio or metadata. This needs research/privacy decisions, not merely colleague UI
feedback, and remains held pending a new decision.

**Branded shortcut icons — optional.** The current Windows shortcut/macOS command launcher
works with default icons. Automatically applying CBS artwork would be a separate platform
change and verification task. There is no commitment to implement it.
